# 工具开发

先阅读 [AGENTS.md](../AGENTS.md)。

本机设置类型放在 `tool-contract`，持久化到原 `config/tool-settings.json`。新增设置同步修改服务端 `machine` 接口和 Web `pages/machine.rs` 表单。读取 DTO 不能包含密码；更新 DTO 使用可选新密码及明确的清除操作。

公开业务设置仍由 `/api/settings` 管理，但写入类型不包含引擎定义与 Git 凭据。引擎通过 `/api/local/engines` 修改。本机来源判断与同源校验统一放在服务端，页面只消费 `/api/access-context` 的能力信息。

路径选择使用 `/api/local/pick-path`，只接受引擎或工作目录两类目的，不提供任意文件读取 API。每次只允许一个系统窗口。修改引擎或工作目录必须独占活动操作保护；拒绝与任务执行交错。

业务任务保留现有配置、状态及日志。新增长任务或外部命令必须接入活动操作保护和受控进程，详见 [退出与任务清理](restart-safety.md)。运行日志可记录阶段、状态和错误，不能打印凭据。

运行根目录列出的格式、测试、Clippy、编译及真实界面检查；npm 发布见 [README](../README.md)。

## 参数与占位符

任务参数的 `type` 支持 `text`、`number`、`switch`、`select`、`identifier`、`version`。英文标识 `identifier` 的非空值只接受 ASCII 英文字母和下划线；服务端保存时统一转小写，包括默认值、选项、组值和预设。配置选项时使用下拉框，否则使用文本框。大小写归一后重复的选项、非法值和占位符名称冲突均拒绝保存，不静默删除数据。

所有用户参数支持 `${param.原始key}` 精确取名并输出保存值。普通文本、数字、选择参数也支持 `${原始key}`。英文标识与开关提供 `${小写key}` / `${大写KEY}`，分别输出小写和大写值，例如 `prod/PROD`、`true/TRUE`。参数 key 不自动改写。现有 `build_mode` 选择定义在校验成功后转换为英文标识；不再经过旧 `BuildMode` 枚举转换取值。

系统占位符为 `version_prefix`、`project_branch`、`project_path`、`engine_path`、`code_package_path`、`remote_package_path`，以及代码/资源路径别名 `code_repo_path`、`asset_repo_path`。准备脚本的 `--project_path` 自动注入。用户参数不可覆盖系统占位符。

替换只进行一遍，未知引用保留原样，参数值中的占位符不会递归求值。构建 JSON、准备参数字符串/选择值和条件来源支持替换；条件“等于”是字面比较。独立准备项目运行没有任务组用户参数上下文。

## 打包页状态

分支缓存按站点、工具 ID、项目 ID 和仓库地址保存在浏览器，首次自动拉取，之后只手动刷新。失败保留缓存；详情与编辑弹窗共享请求，请求不随组件卸载取消。上次任务组使用 localStorage，任务勾选及所属组使用 sessionStorage，存储不可用时保留内存状态。

组内操作仅使用本组勾选。全局启动按页面项目/组顺序及任务顺序提交，同一服务仍只有一个串行队列。`/api/build/status` 增加 `buildInProgress`、`activeTaskId`、`queuedTaskIds`、`cancelRequested`；排队列表不包含正在执行的任务。单独混淆也占用队列。停止操作会取消整个队列。

组参数未保存时阻止相关构建和准备操作，并拦截组切换及站内导航；刷新、关闭使用浏览器离开提示。保存失败保留草稿，保存成功使用服务端规范化结果回显。

## 构建方案与内置版本

每个任务组的 `schemes` 保存完整分支、参数和任务 ID 快照。字段缺失时从当前组创建 pro/test，显式空数组只补建 pro；方案名字不映射分支或构建模式。组内保留一至五项，名称去除首尾空白、忽略大小写判重。浏览器用 localStorage 记录当前关联 ID，首次进入应用首项，之后恢复有效的记忆项；队列占用时等待空闲后初始化。选择方案只恢复当前浏览器本组勾选。

`POST /api/task-groups/{group}/schemes` 新增，`PUT/DELETE .../schemes/{id}` 保存或删除，`PUT .../schemes/{id}/name` 重命名，`POST .../schemes/{id}/apply` 应用。保存同时写入组参数；应用返回组数据、schemeId 及 taskIds。数量、任务归属、版本、参数类型在服务端验证，保存和应用持有队列锁防止与启动交错。任务移动/删除会清理旧方案中的 ID。

内置 `version` 为服务端固定的必填版本号定义，用户只填具体值。`version` 类型接受至少两段 ASCII 数字，用点分隔，以字符串保留前导零。自定义版本参数生成 `${key_prefix}`；前缀截掉最后一个点及后续段。`${version_prefix}` 与资源仓库分支使用同一函数，无组上下文时不引用隐藏项目版本。`/api/parameters/placeholders` 为 Web 共用说明及系统内置区提供统一目录。

提示计时由 App 生命周期拥有，使用唯一消息 ID，弹窗关闭或导航不取消计时，旧计时不会清除新提示。

## 紧凑方案管理与勾选保存

方案切换位于任务组标题旁，管理在标题下展开。本地编辑草稿允许增删、重命名，取消不发请求；保存失败保留草稿。参数类型说明、描述和版本前缀在“？”浮层展示，支持键盘、Escape 和点击外部关闭。参数保存按钮与局部预设共用一行。

- `PUT .../schemes/{id}/tasks` 只接受 `{taskIds}`，校验任务归属、去重，允许队列运行中保存，不改变已提交任务或组参数。
- `PUT .../params` 的 `schemeId` 指向当前方案，分支和完整参数在同一次持久化中写入组和该方案。局部预设使用此接口，保留当前勾选；有参数草稿时先保存或放弃再应用预设。
- `PUT .../schemes/manage` 接受 `currentId`、`schemes: [{id: string|null, name}]` 和新增项使用的 `template`。现有项只更新名称，保留服务端最新内容；新增项复制进入管理时的快照。删除当前项会原子应用剩余首项。至少一项、最多五项的限制也适用于单项删除和新增接口。

勾选保存由 App 生命周期持有，按组与方案串行，约 250ms 合并连续变化。成功回包只更新已保存快照，不覆盖更新的本地勾选；失败显示重试入口。进入管理、切换方案前等待勾选保存；参数草稿或保存失败提供保存、放弃、取消。刷新关闭对未完成写入、失败状态、参数草稿和方案管理草稿给出浏览器提示。
